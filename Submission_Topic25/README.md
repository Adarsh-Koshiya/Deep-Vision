## What was done

Four object detectors were trained and evaluated under matched conditions on the 5-class
Magnetic Tile defect task (blowhole · break · crack · fray · uneven):

| Model | Family | Params | Test mAP50 | mAP50-95 | FPS |
|-------|--------|-------:|-----------:|---------:|----:|
| **Diamond-DETR** | Transformer | 14.3 M | 0.762 | **0.489** | 56.5 |
| RT-DETR-r18 | Transformer | 19.9 M | **0.763** | 0.446 | 40.2 |
| YOLOv8n | CNN | 3.0 M | 0.403 | 0.275 | 205 |
| YOLO11n | CNN | 2.6 M | 0.335 | 0.204 | 153 |

Numbers are reproduced verbatim from `results/metrics/*.json`. Full analysis, limitations,
and per-class breakdowns are in the report.

**Not bundled, the dataset.** To keep the submission small, the raw images and the prepared
YOLO split are *not* included. When re-running, create a `dataset/` folder at the repository root
with the following layout (the scripts and notebook expect exactly this):

```
dataset/
├── Magnetic-Tile-Defect/ raw images + segmentation masks, download from
│ https://github.com/abin24/Magnetic-tile-defect-datasets
└── tile_yolo/ generated by code/prepare_data.py (do not edit by hand):
 ├── images/{train,val,test}/ 938 / 268 / 138 images
 ├── labels/{train,val,test}/ YOLO-format boxes
 └── tile.yaml nc:5, names:[blowhole,break,crack,fray,uneven]
```

Split: **stratified 70/20/10, seed 42 → 938 train / 268 val / 138 test**, zero image overlap
between splits (verified). See `report/REPORT.md` §4 for the conversion details.

## How to reproduce

```bash
# 0. Obtain the dataset first (not bundled, see "Not bundled" above). Download the raw
# Magnetic-Tile-Defect images/masks into dataset/Magnetic-Tile-Defect, then build the
# YOLO split (wipes its own output dir each run, so it is safe to re-run):
python code/prepare_data.py --src dataset/Magnetic-Tile-Defect --out dataset/tile_yolo

# 1. Retrain all 4 models (~15-20 h on an RTX 3060 Ti). FORCE=1 overrides existing metrics:
FORCE=1 bash code/train.sh

# 2. Evaluate a single model (writes results/metrics/<Name>.json):
# YOLO models, from the repository root (stock Ultralytics):
python code/evaluate.py --type yolo --weights weights/yolov8n/best.pt \
 --data dataset/tile_yolo/tile.yaml --name YOLOv8n --out results/metrics
# DETR models, require the bundled fork on PYTHONPATH (the trained best.pt IS included):
PYTHONPATH="code/diamond_detr/RTDETR-main:${PYTHONPATH:-}" \
 python code/evaluate.py --type rtdetr --weights weights/diamond_detr/best.pt \
 --data dataset/tile_yolo/tile.yaml --name Diamond-DETR --out results/metrics
```

The four trained checkpoints (`weights/*/best.pt`) and their metrics (`results/metrics/*.json`)
are already included, so the headline numbers can be inspected without re-running anything.

## Environment

Python 3.12 · torch 2.8.0+cu129 · NVIDIA RTX 3060 Ti 8 GB.
**Two Ultralytics versions are required and cannot share one Python process:** stock 8.4.x
for the YOLO models, and the bundled fork (`code/diamond_detr/RTDETR-main/`, 8.0.201, with
6 applied patches) for the DETR models. `train.sh` and `evaluate.py` already handle the split.
See `docs/CLAUDE.md` and `docs/PROJECT_NOTES.md` for the patch list and rationale.
